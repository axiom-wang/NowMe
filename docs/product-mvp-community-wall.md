# NOWMe MVP 需求文档：社群的墙

标记约定：

- **[已决定]**：本版定下的范围或规则，变更需要重新讨论。
- **[假设]**：产品依赖、尚未经过行为验证的判断，附推翻条件。
- **[待定]**：需要原型、真机或成本测试后才能确定。

## 1. 一句话与方向

**刚进入新圈子的年轻人，和 AI 一起做一页有个性的自己，挂在这个圈子共同的墙上。**

- **创作动力来自表达**：用户想让新圈子看到“像我”的样子，而不是填一张表。
- **分享理由来自共同场景**：圈子里人人都有一页，看别人和被别人看都是正常行为，不需要主动向陌生人推销自己。
- **复用来自新圈子**：每进入一个新圈子，就有理由更新或派生一页，不依赖“持续装修”。


## 2. 目标用户与首批场景

### 首批用户 [已决定]

- 18–24 岁，正在进入新的线下或线上圈子的人。
- 不要求有作品、履历或清晰的设计想法；需要覆盖缺少设计经验的人。
- [假设] 首批用户大多数已经在用自己的编程 Agent（Claude Code、Codex、Cursor 等）。没有 Agent 的成员通过平台托管路线创作（见[页面生成方案](page-generation-byo-agent.md)）。
- 16–17 岁暂不纳入。未成年人的个人信息与内容规则需要单独处理，待产品稳定后另行评估。

### 首批场景 [已决定]

| 场景 | 选择理由 | 时间窗口 |
| --- | --- | --- |
| 黑客松、校园创业营 | 限时、高密度，有组队需求 | 11–12 月可用于原型试跑 |
| 兴趣社群线下活动 | 共同兴趣提供天然话题，表达欲强 | 全年 |
| 社团招新、新成员入群 | 新关系集中出现，组织者入口自然 | 春季学期开学（约 2027 年 3 月）为首个正式窗口 |

单个墙的规模按 10–100 人设计。泛社交、熟人关系、求职与约会不在本版范围内。

## 3. 角色

| 角色 | 定义 | 能做什么 |
| --- | --- | --- |
| **组织者** | 社群或活动负责人 | 建墙、生成邀请入口、移除成员、关闭墙 |
| **成员** | 加入某面墙的人 | 在这面墙上创作并发布自己的页面，浏览其他成员 |
| **主人** | 某一页的创作者（即成员本人） | 管理自己的素材、context、版本、公开范围和联系方式 |
| **墙外访客** | 未加入墙的人 | 只能打开主人单独开启的公开链接 |

组织者**不能**查看成员的素材、context、草稿或对话记录 [已决定]。

## 4. 核心概念

| 概念 | 说明 |
| --- | --- |
| **墙（Wall）** | 一个圈子的共同空间，展示所有已发布成员的缩略卡 |
| **成员关系（Membership）** | 一个人加入一面墙；每段成员关系对应一页 |
| **页面（Page）** | 主人在某面墙上的个性页面；内容、组织和视觉可以自由变化，以沙箱中运行的自包含网页呈现 |
| **场景类型** | 墙的类型（黑客松或创业营、兴趣社群、社团招新、通用），决定页面默认侧重哪一面 |
| **Skill** | NOWMe 提供的生成规范与工具，本地 Agent 和平台托管路线共用 |
| **缩略卡（Card）** | 墙上的入口：名字或昵称、一行介绍、2–3 个可接话的点，可选一张封面图 |
| **Context** | AI 对主人的理解：事实、意图、偏好、边界，带来源、确认状态和适用范围。本地路线中保存在主人本地（长期画像），平台托管路线中保存在平台 |
| **素材（Asset）** | 主人上传或提供的文字、图片、链接 |
| **版本（Revision）** | 页面的一次提交（本地路线）或一次生成、修改结果（平台托管路线） |
| **发布（Publication）** | 主人确认后对墙内成员可见的不可变快照 |

对象关系 [已决定]：

- 一个人可以加入多面墙，每面墙一页，各自独立修改和发布。
- 素材与长期 context 在多页之间共用；“这面墙想突出什么”等意图只作用于当前页。
- 加入新墙时可以从已有页面派生，派生后两页互不影响。

这一结构把墙和缩略卡作为基础层，自由页面作为上层。如果验证表明统一卡片优于个性页，可以去掉页面层，墙与卡片继续使用（见 11.2）。

## 5. 核心流程

### 5.1 组织者建墙

创建墙 → 填写名称、简介 → 点选场景类型，可选填一句话（例如“希望大家写清楚想找什么样的队友”）→ 生成邀请链接与二维码 → 在群公告、报名表或现场物料中发放。

建墙不需要组织者配置模板、字段或风格；场景类型只需点选一次。

### 5.2 成员加入与首次创作

扫码或点链接 → 登录 → 加入墙 → 可以先浏览已有成员 → 选择创作路线：

- **本地路线（免费，默认）**：复制应用给出的指令到自己的 Agent → Agent 拉取墙的情境，读取本地画像，按场景指南采访补全 → 主人确认 brief → Agent 生成页面并自查 → 在本地预览与修改 → 提交到平台。
- **网页内自带 API 创作（平台免费）**：先在账号配置自己的模型服务与 Key，在应用内用一句想法、几张图片、链接或引导开始 → AI 必要时追问 → 平台运行同一个 Skill 生成草稿 → 在应用内反馈与修改。

两条路线之后相同：在应用内预览 → 确认缩略卡上的接话点 → 确认公开内容与联系方式 → 发布到墙。

- 不选模板、不选用途、不填写履历。
- 页面按墙的场景类型侧重不同的一面，例如黑客松突出能力与项目，兴趣社群突出爱好；主人说明了本页意图时以主人为准。
- 信息不足但可以生成时，先给可回应的草稿，不编造个人事实。
- 首次创作的目标耗时与交互次数 [待定]，由原型试跑测出基线后确定。

### 5.3 浏览与联系

进入墙 → 浏览缩略卡 → 打开感兴趣的页面 → 点击接话点上的“想聊这个” → 进入同墙私聊，输入框预填主人确认的开场白 → 修改并主动发送。也可直接发私信，或从墙内全员群的成员列表发起私聊，无需先发布自己的页面。外部联系方式使用独立入口，只展示主人明确公开的内容。

每面墙自动有唯一全员群，加入墙即可参与。私聊与群聊均仅支持文字，提供会话列表、历史分页、未读数与新消息自动更新。退出或被移出的用户立即失去该墙全部会话和历史记录的访问权限；墙关闭后所有人失去访问权限。组织者不能查看他人私聊。

### 5.4 修改与更新

本地路线：在 Agent 中补充素材或用日常语言提出修改 → 提交新版本 → 在应用内预览对比 → 确认后更新发布版本。

平台托管路线：在应用内补充素材或提出修改 → 预览对比 → 接受、撤销或恢复 → 确认后更新发布版本。

局部修改不改变其他已认可部分；恢复旧版本在应用内完成。

### 5.5 撤下与退出

- 主人可以随时从墙上撤下自己的页面，或退出墙。
- 主人删除页面或素材前，系统说明影响范围，由主人确认。

### 5.6 进入新圈子

加入新墙 → 选择从已有页面派生或重新开始 → Agent 对比新旧墙的场景类型，建议哪些内容保留、哪些弱化、需要补什么 → 主人修改后发布。

## 6. Context 机制

沿用 10 月版第 5 节的定义：**模型获得足够的信息，能做出用户认可的表达选择，并根据反馈越来越准确地修改。**

| 类别 | 内容 | 默认适用范围 |
| --- | --- | --- |
| 个人素材与事实 | 兴趣、照片、经历、作品、原文 | 主人的所有页面 |
| 展示意图 | 这面墙想突出哪一面、希望传达什么 | 当前页面 |
| 表达偏好 | 视觉、语气、布局、交互偏好 | 当前页面；主人明确认可后才成为长期偏好 |
| 表达边界 | 不展示的信息、不接受的表达 | 按主人明确的范围；范围不清时先确认 |

规则 [已决定]：

- 每条记录保存来源、确认状态（主人明确表达、主人确认、模型暂定）、适用范围、更新时间与有效性。模型暂定内容不得作为事实展示。
- 下一次追问只问会明显改变结果、又容易回答的问题；可以跳过，已知信息不重复问。
- 明确纠正使旧记录失效；撤销页面修改时同步恢复相关的创作状态。
- 恢复旧版本或派生新页，都不会自动扩大公开范围，也不会让已删除的信息重新出现。
- 主人能用日常语言查看与纠正 AI 的关键理解，无需操作内部字段。
- 墙上可见的只有已发布内容；context、草稿与对话记录始终私有。
- 信息怎样收集、按场景问什么、本地路线的隐私规则，见[信息收集与 brief](brief-collection.md)。

## 7. P0 功能需求与验收标准

| 编号 | 功能 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| W01 | 账号与登录 | 用邮箱登录，找回自己的页面与成员关系 | 换设备或重新进入后能继续编辑；他人不能编辑主人的内容 |
| W02 | 建墙 | 组织者填写名称、简介，点选场景类型并可选填一句话，生成邀请链接与二维码 | 3 分钟内完成建墙；不需要配置模板或字段 |
| W03 | 组织者管理 | 查看成员列表与发布状态，移除成员，关闭墙 | 被移除成员的页面立即从墙上消失；组织者界面中没有 context、草稿或对话入口 |
| W04 | 加入墙 | 通过邀请入口加入，加入后即可浏览已发布成员，不需要先发布自己的页面 | 无邀请入口不能加入；未发布的成员不出现在墙上 |
| W05 | 创作入口 | 本地路线：显示带一次性 token 的 Agent 指令；网页路线：支持账号配置自己的 AI API，然后用自由文本、图片、链接与可跳过的引导创作 | 复制指令即可在 Agent 中开始；token 一次性、只对本页有效，首次使用时换成页面凭证，之后可多次提交（见[页面生成方案](page-generation-byo-agent.md)第 6.1 节）；token 有效期见[信息收集与 brief](brief-collection.md)第 6 节；托管路线一句想法或几张图片即可开始；不需要选模板或用途 |
| W06 | Context 获取与维护 | 按第 6 节分类、记录、纠正与删除；本地路线保存在主人本地画像中，平台托管路线保存在平台 | 不重复问已知信息；纠正后不再复现；当前页的意图不自动成为长期偏好；brief 经主人确认后才用于生成 |
| W07 | 生成 | 由同一个 NOWMe Skill 生成可预览页面，在本地 Agent 或平台运行；按墙的场景类型侧重不同的一面 | 相同素材、不同意图或不同场景能得到组织或表现明显不同的结果，不只是换颜色；页面通过平台校验 |
| W08 | 编辑 | 用日常语言修改内容、顺序、配色、布局与语气；可限定修改某个区块。本地路线在 Agent 中修改，平台托管路线在应用内修改 | 局部修改只改变目标部分（按区块的稳定标识）；作用范围不清时先澄清；原素材保留 |
| W09 | 素材管理 | 上传、替换、删除图片，维护文字和链接 | 上传失败可重试且不丢失已有输入；图片数量与大小限制 [待定] |
| W10 | 版本 | 每次提交或生成存为一个版本；接受、撤销、恢复已保存版本 | 撤销后页面与创作状态一致；生成失败或校验不通过不覆盖可用版本 |
| W11 | 缩略卡 | AI 从页面提取一行介绍与 2–3 个接话点，主人确认或改写后显示 | 未经主人确认的接话点不出现在墙上；接话点具体、可回应，不是抽象标签 |
| W12 | 发布到墙 | 展示最终预览，确认公开内容与联系方式后发布 | 只有确认发布的内容对墙内成员可见；更新失败不影响已发布版本 |
| W13 | 墙浏览 | 网格展示已发布成员的缩略卡，点击进入页面 | 手机上流畅浏览 100 张卡；每次进入随机排序，不按热度排名 |
| W14 | 想聊这个与墙内聊天 | 接话点进入站内私聊并预填开场白；每墙一个全员群；公开联系方式另行保留 | 文字收发、分页历史、未读数与自动更新；开场白不自动发送；未公开联系方式也可私聊；同墙有效成员可参与，失去墙权限后聊天与历史立即不可访问 |
| W15 | 访问权限 | 页面默认只对墙内成员可见；主人可单独开启公开链接，也可随时关闭 | 非成员打开墙或未公开的页面时看不到内容；关闭公开链接后原链接失效 |
| W16 | 撤下、退出与删除 | 主人可撤下页面、退出墙、删除页面或素材 | 撤下后墙上立即消失；删除前说明影响范围并确认 |
| W18 | 派生到新墙 | 加入新墙时从已有页面复制一份 | 派生页的修改不影响原页；原页的公开范围不被继承 |
| W19 | 能力范围与失败处理 | 说明生成状态、可重试错误、校验失败原因与不支持的请求，并给出修复指引或替代方案 | 不静默忽略请求，不声称完成未实现的效果；校验失败给出具体原因；素材、context 与可用版本保留 |
| W20 | 行为记录 | 记录第 10 节所需事件；本地路线由 `nowme` 工具上报开始、生成、提交等事件 | 能按墙统计浏览、打开、“想聊这个”、修改与派生；本地路线只上报事件，不传内容；记录不包含页面以外的私密内容 |
| W21 | 页面校验与沙箱 | 平台重新校验每次提交，在独立域名的沙箱中展示页面 | 不信任客户端校验结果；页面无法联网、读取主站登录状态或跳转顶层页面；审核以渲染后的文字和截图为准 |
| W22 | AI 介绍值得认识的人 | AI 读成员自己的资料与墙上的人，主动介绍几位适合认识的（能一起学习、兴趣相投、可以合作），说明理由并接到“和 TA 聊什么” | 第一次进墙自动出现、之后由成员手动换一批；每条理由的依据是两边页面上的原文；只有本人看得到，被介绍的人不会收到通知；只在同一面墙内，不跨墙推荐（contracts 20） |
| W23 | 问墙：用一句话找人 | 成员在墙上问一句（“谁会剪视频？”“谁也在准备考研？”），AI 读墙上公开的页面，找出写到这件事的人并附上 TA 页面上的原话，再接到“和 TA 聊什么” | 不需要先有自己的页面；每一位的依据是对方页面上的原文，AI 不替别人编；没人写到时如实说没找到；提问与结果只有本人看得到，被找到的人不会收到通知；只在同一面墙内（contracts 21） |

页面能力的首期范围 [已决定]：自包含网页，可以使用 CSS 动画、Canvas、WebGL、SVG 与交互脚本；不能联网、不能存储、不能跳转顶层页面。具体约束见[页面生成方案](page-generation-byo-agent.md)第 5.2 节。

## 8. 页面结构

1. **我的**：我加入的墙、我的页面及各自的发布状态、开始新创作。
2. **创作工作区**：提供账号 AI 设置入口（服务、地址、Key、采访和生成模型）；未配置时引导填写，不隐藏入口。Key 加密保存在账号下，跨设备可用，可更换、删除且不回显；模型费用由用户向服务商支付。本地路线显示 Agent 指令、本地 Agent 的连接状态（可断开）与最近一次提交时间；平台托管路线提供对话与素材输入；两者都有页面预览、版本面板、发布确认。
3. **墙**：墙的名称与简介、成员缩略卡网格、“我的页面”和全员群入口。
4. **成员页面**：主人的页面、接话点与“想聊这个”、直接私聊和公开联系方式入口。
5. **组织者后台**：建墙、邀请入口、成员与发布状态、关闭墙。
6. **消息**：跨墙会话列表、未读数、各墙全员群入口；聊天页显示文字历史与输入框，全员群可查看有效成员并发起私聊。

小屏幕上的对话、预览与区块选择方式（平台托管路线）需要原型验证，避免用户为了修改反复寻找目标。

## 9. 范围边界

| 优先级 | 内容 |
| --- | --- |
| P0 | 第 7 节全部功能 |
| P1 | 按接话点关键词筛选墙；墙内共同点提示；更多可靠的视觉与交互能力；接入成员已有的公开资料 |
| 已决定 | 本地 Agent + 网页内自带 API 创作；取消按墙收费、个人付费和平台免费次数。平台服务器使用用户 Key，模型费用由服务商直接向用户收取。详见[页面生成方案](page-generation-byo-agent.md)第 9 节 |
| P2 | 语音创作、视频与音频上传、组织者跨墙数据 |
| 不做 | 跨墙陌生人私信、自由建群、聊天图片/文件/音视频、关注、信息流、公开广场与陌生人推荐（W22 只在同一面墙的成员之间介绍）、点赞与访问排行、访客 AI 问答（W23 只对墙内成员、只在墙内公开的页面里找人）、电商与任意业务系统 |

## 10. 指标

### 北极星候选

**加入墙的成员中，浏览过 3 页以上且至少使用一次“想聊这个”的人数比例。**

“想聊这个”只代表开口意图，不代表真的发生了对话。原型与试跑阶段需要通过现场观察与会后访谈，记录能追溯到页面内容的真实对话，校准这个代理指标。

### 配套指标

| 环节 | 指标 |
| --- | --- |
| 组织者 | 建墙后发放邀请的比例；成员加入率 |
| 创作 | 加入到发布的转化；首次发布耗时、交互次数与费用；“像我”的自评 |
| 浏览 | 每位成员打开的页面数；缩略卡点击率 |
| 联系 | “想聊这个”使用率；会后访谈中可追溯对话的比例 |
| 修改 | 修改达成率；局部修改造成的无关变化；已纠正问题的复现 |
| 延续 | 发布后 7 天内的主动修改；开启公开链接的比例；派生到新墙的比例 |
| 稳定与成本 | 生成、修改、发布成功率；每个已发布页面的模型费用 |

成功阈值在每轮验证开始前写定，结果出来后不调整。

## 11. 关键假设与推翻条件

### 11.1 假设清单

| 假设 | 观察什么 | 推翻条件 |
| --- | --- | --- |
| H1 在共同场景中，成员会浏览别人的页面 | 浏览 3 页以上的比例 | 多数成员只看自己，或看不到 3 页就离开 |
| H2 个性页比统一卡片更能促成开口 | 同类场景下两种形式的联系与可追溯对话 | 两者接近，或卡片更好 |
| H3 用户愿意参与 AI 共同创作 | 加入到发布的转化、耗时、放弃位置 | 大量用户在创作中途放弃，或要求“直接给我一张卡” |
| H4 组织者愿意建墙并推动成员加入 | 建墙与发放邀请的比例 | 组织者普遍不愿配合 |
| H5 页面在活动结束后仍有价值 | 活动结束后的访问、修改、派生 | 活动结束后几乎没有任何使用 |
| H6 局部编辑能稳定完成 | 修改达成率与无关变化 | 多数修改造成整体漂移或内容丢失 |

### 11.2 降级路径

- **H2 不成立**：去掉自由页面层，保留墙与缩略卡，转向更轻的卡片或活动名录。
- **H1 或 H4 不成立**：停止社群方向，不再依靠优化页面补救。
- **H1 成立但 H2、H3 弱**：保留墙，降低创作自由度，以采访加确认为主。
- **H5 不成立**：按季节性的社群工具评估，产品节奏围绕招新季与活动季。
- **成员自发把页面分享到墙外**：才有依据向通用个人主页扩展。

## 12. 约束

### 隐私与合规 [已决定]

- 页面默认只对墙内成员可见；公开链接由主人主动开启。
- 组织者不接触成员的私密内容；行为记录用于产品统计，不向组织者提供个人层面的浏览轨迹。

### 技术 [已决定]

- 页面由 NOWMe Skill 生成自包含网页，主要区块有稳定标识（`data-nm-id`），便于局部修改。本地路线由用户的 Agent 运行，平台托管路线由平台运行同一个 Skill。详见[页面生成方案](page-generation-byo-agent.md)。（取代 2026-11-02 的“先走结构化页面路线，代码生成只作为对照实验”。）
- 页面放在独立域名下的沙箱 iframe 中，配严格 CSP；平台对每次提交重新校验，并用无头浏览器渲染后审核。
- 墙上只显示静态封面，点进页面才运行。
- 不为每个用户创建长期的运行或部署环境；页面以静态文件托管，平台托管路线的生成任务在隔离环境中运行、结束后清理。
- 可借鉴的内部资产：MGX 的版本关联方法、FuncSea 的账号与基础服务。FuncSea 的图片上传需要重写。详见[复用评估](deepwisdom-reuse-assessment-2026-10-07.md)。
