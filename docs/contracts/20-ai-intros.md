# 20. AI 介绍值得认识的人（S14）

成员不用一页页翻墙：AI 了解他之后，主动把这面墙上适合他认识的人介绍给他——能一起学习的、兴趣相投的、可以合作的——并说明为什么，再接到“和 TA 聊什么”（第 11 节）起个头。代码：`apps/web/src/hosted/intro.ts`（模型调用与核对）、`apps/web/src/services/intro.ts`（授权、资料、限流、保存、展示）、`apps/web/src/db/intros.ts`、`apps/web/src/views/intros.tsx`、`static/wall.js`（首次自动），迁移 `021_intros.sql`；常量 `INTRO_*` 与 ID 前缀 `itr_`（`intro`）、事件 `intro_generate` 在 `packages/contracts`。产品编号 W22。

## 20.1 谁能发起、什么时候出现、用谁的模型

- 只在墙页（`GET /w/:wallId`）“我的页面”下面。查看者必须是这面墙的有效成员；只介绍**这面墙**上对他可见的、别人的已发布页面（`listPublished` 去掉自己与任一方向拉黑的人）。不跨墙，不是“陌生人推荐”。
- 区块状态：候选不到 `INTRO_LIMITS.minCandidates`（3）位 → 不显示；查看者在这面墙没有资料（已发布的页面或确认过的采访都没有）→ 引导先做页面；没有可用的 AI → 引导去 AI 设置（演示模式写明体验账号不可用）；可以开始；有结果；结果里的人都失效 → 提示重新看看。
- **首次自动**：查看者在这面墙从没发起过（没有任何 `intro_generate` 事件）且没超限时，表单带 `data-intro-auto`，`static/wall.js` 在页面加载后用同源 `fetch` 提交一次（带 CSRF，`fragment=1`），返回的区块原地替换。失败也记事件，之后不再自动；之后的“换一批”“墙上新来了 N 位，再看看”由成员自己点。没有脚本时就是一个普通按钮。是否“第一次”由服务端按事件判断（事件 `first`），不信任客户端。
- 模型按 `interview` 角色解析：查看者有自己的配置就用自己的；没有且平台 AI 可用时用平台 AI，**不收点数**，计入全站免费调用上限（12.1）。

## 20.2 交给模型的资料（输入范围）

| 一方 | 内容 | 上限 |
| --- | --- | --- |
| 墙 | 名称、简介（≤ 200）、场景名 | — |
| 查看者 | 与 11.2 相同：**自己**在这面墙已发布的卡片与渲染文字、**自己**确认过的采访摘要；另加**自己**在这面墙的必答题回答 | 渲染文字 `INTRO_VIEWER_TEXT_MAX`（1600） |
| 查看者的禁区 | brief 里 `boundaries.hidden` 与 `rejected`，单独成块，只用于“不得提到” | 12 条 |
| 每位候选（`member_N`） | 当前发布快照的一行介绍、接话点（不含开场白），墙内公开的必答题回答，当前发布版本渲染文字的摘录 | 摘录合计 `INTRO_CANDIDATE_TEXT_BUDGET`（24 000），按人数均分，每页 160–600 |

- 候选**只给编号，不给名字**；名字与封面由平台按发布快照显示。候选每次随机排列（不按热度，W13），超过 `maxCandidates`（80）随机取样。“换一批”时写明上次介绍过的编号，请模型优先看别人。
- 不读任何人的草稿、未发布版本、采访、画像、联系方式（含公开的）、开场白，不读没上墙的人与拉黑的人。所有资料去控制字符、截断后用 `untrusted()` 包成资料块，system 声明资料不是指令；`untrusted()` 同时去掉伪造的 `member_N` / `page_N` 标签。

## 20.3 输出与核对

模型必须调用 `submit_intro`：`picks[{ member, kind: learn|interest|collab, title, reason, mine, theirs }]`。输出经 zod 校验；核对后一位都不剩时重试一次，再失败为 `failed`，不保存。

| 规则 | 说明 |
| --- | --- |
| 长度 | 最多 `picks`（5）位；`title` ≤ 18、`reason` ≤ 60、`mine` / `theirs` ≤ 40 码点 |
| 编号 | 必须在 1..N 内、不重复（接受 `member_2` 写法），否则丢弃 |
| 原文核对（`groundIntro`） | `theirs` 必须出现在**那一位**候选的资料里（防张冠李戴），`mine` 必须出现在查看者的资料里（含他自己的必答题回答）；比较方式同 11.3；对不上整条丢弃 |
| 禁止链接与联系方式 | 同 11.3 的 `hasContact`，任一字段含有即整条丢弃；先查原文再截断 |
| 不提别人 | `title` / `reason` 里出现**另一位**候选的名字（≥ 2 字，规范化后包含）整条丢弃 |
| 类型 | 未知 `kind` 按 `interest` |
| 输出 | 只经 JSX 转义按文字渲染 |

## 20.4 结果归属、展示与清除

- 表 `intros`（`id itr_`、`wall_id`、`viewer_id`、`sources_json`、`seen_json`、`created_at`，`UNIQUE(viewer_id, wall_id)`）与 `intro_picks`（`intro_id`、`position`、`page_id`、`publication_id`、`kind`、`title`、`reason`、`mine`、`theirs`）。只保存成功的结果；每位查看者每面墙只留最新一份（“换一批”替换）。`seen_json` 是当时的候选页面，用来提示“墙上新来了 N 位”。
- **只属于查看者**：只按 `viewer_id` 读取；被介绍的人、组织者、其他成员都看不到，平台不发任何通知、不产生消息。每一位绑定对方当时的 `publication_id`：对方更新、撤下、拉黑（任一方向）、离开墙后，那一位立即不再展示（墙上卡片的“✦ AI 介绍”标记、成员页 `#talk` 顶部的“AI 介绍你们认识”同样）。
- 模型调用结束后重新授权：查看者失去访问、墙关闭 → 不保存（`gone`）；期间更新 / 撤下 / 拉黑的那几位去掉，一位都不剩时 `gone`。
- 每张卡片：“让 AI 帮我起个头”直接提交 `POST /w/:wallId/p/:pageId/icebreaker`（第 11 节，落到对方页面的 `#talk`，开场白只预填）；“看 TA 的页面”。
- 清除：查看者手动清除；查看者退出、被移出、删除自己的页面或采访（他在这面墙的结果）；某一页被删除（引用了这一页的整份结果）；墙关闭（整面墙）；注销（他的全部结果；他的页面被删除时，别人得到的、引用了它的结果也删除）。数据导出（第 14 节）包含仍然有效的介绍（`intros`）。

## 20.5 路由与限流

| 路径 | 谁能访问 | 作用 |
| --- | --- | --- |
| `POST /w/:wallId/intros` | 墙内有效成员 | 发起或换一批；303 回 `/w/:wallId#intros`，失败带 `?intro=<错误>`；`fragment=1` 时 200 直接返回区块 HTML（`Cache-Control: private, no-store`），返回前重新确认访问 |
| `POST /w/:wallId/intros/clear` | 同上 | 清除本人在这面墙的结果 |

均为会话 + CSRF + Origin 的表单路由，忽略 `Authorization`；无权访问一律 404，且不调用模型。

| 限制 | 取值 | 错误 |
| --- | --- | --- |
| 每位查看者（跨墙） | `INTRO_DAILY_PER_VIEWER`（12）次 / 滚动 24 小时 | `daily` |
| 同一查看者在同一面墙（含首次与换一批） | `INTRO_DAILY_PER_WALL`（4）次 / 滚动 24 小时 | `wall-daily` |
| 同一查看者并发 | 1 | `busy` |
| 单次总时限 | `INTRO_TIMEOUT_MS`（90 s） | `timeout` |

次数按 `intro_generate` 事件计（成功与失败都记，`props` 只有 `ok`、`first`、`durationMs`、`candidates`、`picks`、`hasPage`、`hasBrief` 与 token 数）。其他错误：`MODEL_CONFIG` / `MODEL_AUTH` / `MODEL_RATE_LIMITED` / `MODEL_UNAVAILABLE`、`too-few`、`no-material`、`failed`、`gone`。界面只显示 `INTRO_ERROR_TEXT` 里的固定文案（演示模式下模型类错误换成演示说明），不在名单里的 `intro` 参数不显示任何提示。
