# NOWMe 信息收集与 brief

本文说明页面生成的第一步：怎样用尽量少的交互，从主人那里拿到足够做出"眼前一亮"页面的信息，并整理成交给生成环节的 brief。

与其他文档的分工：

- [MVP 需求文档](product-mvp-community-wall.md)第 6 节定义 context 的类别、确认状态和通用规则，本文不重复。
- [页面生成方案](page-generation-byo-agent.md)说明两条路线、Skill、生成、校验与托管；本文只负责生成之前的部分。

标记约定同 MVP 文档：**[已决定]**、**[假设]**、**[待定]**。

## 1. 原则 [已决定]

- **要具体细节，不要填满字段**：做出"眼前一亮"的页面，靠的是几个具体、别人没有的细节（"总在凌晨四点去菜市场拍摊主的手"），而不是"喜欢摄影"。
- **事实和边界在生成前收集，风格在看到草稿后调整**：

  | 类别 | 何时收集 | 理由 |
  | --- | --- | --- |
  | 事实、原话、边界 | 生成前 | 生成时不能编造，缺了以后补不回来；边界错了有风险 |
  | 本页意图 | 生成前，一道选择题 | 直接决定页面怎么组织，回答代价低 |
  | 风格偏好 | 生成前只收一个粗略信号，其余在修改阶段调整 | 人说不清自己要什么，但看到草稿很容易说"不要这种" |

- **信息只来自采访问答**：不从 Agent 已有的上下文里推断，也不主动读取主人本地或网络上的其他资料来补充。主人可以主动提供图片和文件（第 5 节）。
- **两条路线同一套方案**：本地路线由用户的 Agent 采访，平台托管路线由平台在应用内采访；流程、场景指南和 brief 结构完全相同，只是交互形式不同。

## 2. 信息从哪里来

| 层 | 内容 | 谁提供 | 采访时怎么处理 |
| --- | --- | --- | --- |
| 墙的情境 | 场景类型，加上组织者的一句话（可选） | 平台，建墙时设定 | 不用问，直接拉取 |
| 长期画像 | 主人之前确认过的技能、项目、兴趣、经历、偏好 | 主人，历次采访积累 | 不用问，只问这面墙需要而画像里缺的 |
| 本页意图与新信息 | 这一页想突出什么，以及这次新补充的事实 | 主人，本次采访 | 本次采访的重点 |

生成时按墙的情境从画像中**挑出一部分、换一种讲法**，所以同一个人在不同墙上的采访，问的东西也不同。

## 3. 采访流程

| 步骤 | 做什么 | 本地路线 | 平台托管路线 |
| --- | --- | --- | --- |
| 0. 不用问的先拿到 | 墙的情境；主人已有的长期画像 | 读取本地画像（例如 `~/.nowme/profile.md`） | 读取平台保存的画像 |
| 1. 先收素材 | "贴任何关于你的东西"：写好的自我介绍、作品链接、几张照片；提示语按场景指南。从中抽取第一批事实候选 | 在 Agent 对话中粘贴或给出文件 | 应用内一个输入框 |
| 2. 选择题 | 场景指南中的选择题；风格从 6 张缩略图中选 1–2 张（对应 Kit 示例页）；动效强度三档；边界多选，按场景预选默认项 | Agent 以编号选项提问 | 应用内点选 |
| 3. 追问 | 最多 2–3 个，按场景指南的追问方向挖具体细节；每个问题给出回答选项，可跳过 | 同左 | 同左 |
| 4. 确认"AI 眼中的你" | 把 brief 写成几句通顺的话，附接话点候选；主人可以划掉或改写，确认后才进入生成 | Agent 展示，主人在对话中确认 | 应用内确认 |

- **先收素材再提问**：粘贴已有内容比回答问题省力得多，信息量也更大。
- **判断是否足够**：满足场景指南中"生成前必须有"的各项即可生成。"够了，去生成"始终可选；必须有的项缺失时，说明缺什么、为什么需要。
- **第 4 步的作用**：执行"只用主人确认过的信息"的规则；修正抽取时的误读；也让主人在生成之前就觉得"它懂我"。
- **写回画像**：新确认的长期信息写回画像；本页意图只留在这一页。
- **派生到新墙**：从已有页面派生时，对比新旧墙的场景指南，只问新场景"生成前必须有"而画像里缺的信息，并建议哪些内容保留、哪些弱化。
- **平台托管路线的费用**：约 2–3 次小模型调用（抽取素材并生成追问、整理 brief，必要时再追问一次）；固定的 system prompt 开启 prompt caching，场景指南作为变量注入。

## 4. 场景指南

采访流程在所有场景下相同，场景指南只改变每一步的具体内容。

| | 黑客松 / 创业营 | 兴趣社群 [假设] | 社团招新、新成员入群 [假设] |
| --- | --- | --- | --- |
| 这页要解决什么 | 几小时内找到队友 | 在共同兴趣里找到"同频的人" | 在一个长期圈子里被记住 |
| 采访耗时预算 | 约 90 秒（签到时、开幕前） | 约 2 分钟 | 约 3 分钟，不赶时间 |
| 素材提示 | "贴一个你做过的东西：链接、截图、一句话描述都行" | "贴几张和这个爱好有关的照片：作品、收藏、现场" | "贴一段自我介绍或几张能代表你的照片" |
| 选择题 | 角色（开发 / 设计 / 产品 / 其他）、技能标签、**想找什么样的队友**、想做的方向 | 入坑多久（新手也欢迎）、偏创作 / 收集 / 交流、**想找人一起做什么** | **新成员还是老成员**、年级和专业（可跳过）、想在社团里尝试什么、社团之外的爱好 |
| 追问方向 | 做过的一个具体项目：解决了什么、你负责哪部分；这次的想法有多具体 | 这个爱好里你独特的角度：最痴迷的作品或物件、入坑的故事 | 一个让人记住你的具体细节：奇怪的技能、最近在沉迷的事；为什么来这个社团 |
| 生成前必须有 | 角色 + 至少 1 项技能 + 想找什么样的队友 + 1 个具体项目或想法 | 个人角度 + 1 个具体作品或喜好 + 1 件想一起做的事 | 1 个具体细节 + 想尝试的事 + 1 个社团之外的爱好 |
| 接话点类型 | "我能帮你做 X"、"找会 Y 的队友"、"我想做 Z" | "推荐你看 X"、"求带 Y"、"想找人一起去 Z" | "可以来问我 X"（老成员）、"我也想试 Y"、"我在沉迷 Z" |
| 默认边界 | 显示学校（组队有用）；联系方式默认公开 | 用昵称，不显示学校；联系方式默认不公开 | 显示年级和专业；联系方式默认不公开 |
| 页面目标（写进 brief） | 首屏和封面一眼看出角色和想找什么人；信息密度可以高 | 作品或爱好是视觉主角，个人信息靠后 | 突出个性和趣味，可以更玩一点 |

**通用场景**：意图选项更宽泛，追问只挖具体细节，生成前必须有"3 个具体事实 + 1 个本页意图"。

两点说明：

- **黑客松只有一道必答题**："想找什么样的队友"是这类墙最核心的信息，不能跳过；其余都可以跳过，追问最多 1 个。
- **社团墙先分新老成员**：新成员想被认识，老成员是"可以来问我"的人，后面的选项和接话点随之不同。

规则：

- 场景指南只给默认方向。主人说明了本页意图时，以主人为准。
- 每个场景一份配置文件（JSON），包含上表各项。平台托管路线直接读取；本地路线由 Skill 随附同一份配置。新增场景只需加一份配置，不改代码。
- 生成侧的场景差异（建议区块、视觉基调）见[页面生成方案](page-generation-byo-agent.md)第 3 节。

## 5. 主人主动提供的图片和信息

- **图片和文件**：主人可以在采访或修改时把本地图片、文件交给 Agent。图片放进 `page/assets/`，提交时上传到平台并经过内容审核。主人是主动提供的，不需要再单独确认。
- **修改时补充的说法**：主人在修改时直接对 Agent 说的新信息（例如"再加一句我拿过校赛二等奖"），属于"主人明确表达"，可以直接使用；其中的长期信息写回画像。
- 发布前主人会在应用内预览整页，不另设逐条确认。

## 6. 本地路线的隐私规则 [已决定]

- Agent **不主动翻找**主人的文件、聊天记录或其他项目，也不使用自己已有上下文中关于主人的信息；只使用本次采访中主人回答的内容和主动提供的文件。
- "模型暂定"的推测不进入 brief。
- 画像和 brief 保存在本地、不上传平台，平台只收到最终提交的页面。
- 指令中的一次性 token 只对这一位成员的这一个页面有效，首次拉取时换成页面凭证后立即失效；之后的提交使用页面凭证（[页面生成方案](page-generation-byo-agent.md)第 6.1 节）。token 的有效期要覆盖"活动现场在手机上拿到指令、当晚回到电脑上才执行"的情况，具体时长 [待定]。

## 7. brief 结构

| 字段 | 内容 |
| --- | --- |
| 墙的情境 | 墙的名称、简介、场景类型、组织者的一句话 |
| 页面目标 | 来自场景指南：首屏必须呈现什么、推荐的示例页 |
| 事实与素材 | 主人确认过的兴趣、经历、作品、图片 |
| 原话 | 主人自己的说法，生成时优先直接引用，比改写更"像他" |
| 重点细节 | 最有意思的 1–2 个细节，作为页面的视觉重点 |
| 本页意图 | 这面墙想突出哪一面、希望别人看完记住什么 |
| 表达偏好 | 风格参考的示例页、语气、动效强度等，可以为空；只作参考，不作硬性规则 |
| 表达边界 | 不展示的信息、不接受的表达 |
| 未知与不要猜 | 采访中没有得到的信息，生成时不得补全或猜测 |
| 接话点候选 | 2–3 个具体、能接话的点，类型参照场景指南 ||
