# 黑客松评审演示（本地，不部署）

`pnpm demo` 保留现有 Hono SSR、SQLite、独立源页面托管、本地 Agent 和示例数据重建流程。启动前先检查两个内部端口；首次初始化 `.data/demo`，后续启动保留已有页面、聊天、发布状态与会话。仅 `pnpm demo --reset` 会清空重建，请先备份重要数据。普通 `pnpm dev` 不开放快捷登录，不读取演示模型变量。

## 统一启动与打开

比赛体验只需运行 `pnpm demo`，然后打开 `http://localhost:3000`。主站与页面沙箱由同一个服务进程管理，按 Ctrl+C 一起关闭，无需启动首页、AI 或徒步的独立检查服务。后台仍保留 `localhost:3000` 和 `127.0.0.1:4000` 两个来源，维持 cookie 与沙箱隔离；不用直接打开 4000。

普通开发使用 `pnpm dev`，同样在一个服务进程里启动两个来源，支持修改源码后重载，使用普通 `.data` 数据。两种命令共用端口，同一时间只运行一种。单包的 `start:source` 仍保留给自动化测试使用。

已有演示数据库只恢复运行，不会自动追加新版本的背景数据；需要刷新整套种子数据时，备份后执行 `pnpm demo --reset`。

## 维护者配置

将 `.env.demo.example` 中需要的条目复制到仓库根的 `.env.local`（已被 Git 忽略），或在启动进程前设置服务端环境变量。示例文件只含占位符，不要向其中填写真实 Key。环境变量优先于 `.env.local`，其次是 `.env`。

- `NOWME_AI_ENCRYPTION_KEY`：64 位十六进制随机主密钥，继续用于现有 AES-256-GCM；不要提交或放入数据库。
- `NOWME_DEMO_PROVIDER`：现有服务商标识，例如 `deepseek`、`anthropic`、`openai-compatible`。
- `NOWME_DEMO_BASE_URL`：公网 HTTPS 的 API 根地址，不包含 `/chat/completions`；可留空采用所选服务的现有预设。
- `NOWME_DEMO_MODEL`：真实模型名称，须支持工具调用。
- `NOWME_DEMO_API_KEY`：演示提供者的真实 Key。
- `NOWME_DEMO_VISION`：`0` 或 `1`；省略时采用服务预设。不支持看图的模型使用 `0`。

上述配置由采访和生成共用。分别设置时，使用 `NOWME_DEMO_INTERVIEW_` 与 `NOWME_DEMO_GENERATE_` 前缀加 `PROVIDER` / `BASE_URL` / `MODEL` / `API_KEY` / `VISION` 覆盖对应角色，其余沿用公共配置。更换角色服务或地址时须同时提供该角色的 Key，避免将公共 Key 发给另一服务。也支持完全不填公共项、分别填两个角色全部必要项。

若本地代理把域名解析为 `198.18.*` 等 fake-IP，现有网络策略会正确拒绝。维护者可显式设置 `NOWME_DEMO_DNS_SERVERS` 为可用的 DNS 服务器 IP（多个用逗号分隔，例如 `1.1.1.1`）；仅演示启动使用，每次请求仍解析 A/AAAA、检查全部结果，并固定实际公网连接地址，拒绝保留/内网地址和重定向。不配置时沿用系统 DNS。

例如 DeepSeek 可选择 `deepseek`，API 根地址 `https://api.deepseek.com/v1`，模型 `deepseek-chat`，看图关闭；真实可用性取决于服务商账号的权限、余额和当前模型。此处不保存真实 Key。

启动时通过现有 `userModels.save()` 原子写入体验成员账号的两个角色：随机 nonce、认证加密、AAD 绑定用户/角色/版本/端点。仅数据库密文持久化；不向评委、浏览器、日志、提示词或页面文件输出 Key。预置不发模型请求，状态“已配置”仅表示配置可读取；实际可用性必须通过真实请求验收。

没有提供演示配置时，浏览与本地 Agent 仍可用，终端、工作区和采访页明确要求维护者补齐。配置不完整、密钥格式错误或地址无效时启动明确失败。评审演示禁止 `NOWME_MODEL_FAKE` / `NOWME_CLAUDE_FAKE` 和测试模型注入，不会静默回退。网络访问、DNS 固定连接地址、拒绝重定向、任务隔离、凭证版本失效继续沿用现有实现。

## 两个体验身份

未登录时，首页与 `/login` 都展示两个按钮，不需要邮箱、验证码或注册：

| 按钮 | 固定账号（仅维护者参考） | 进入位置 | 能力 |
| --- | --- | --- | --- |
| 以成员身份体验 | `newbie@demo.nowme.test` | 首页 `/`，从墙卡片进入工作区 | 浏览人物墙，采访、资料确认、真实生成、修改、沙箱预览、本人确认发布 |
| 以组织者身份体验 | `organizer@demo.nowme.test` | 首页 `/`，从墙卡片进入组织者后台 | 按原有组织者权限管理成员和邀请，不能查看他人的草稿、版本和采访资料 |

保留原有黑客松墙、社团墙，以及 AI 共创和山野轻徒步墙与人物页；城市漫游、独立创作两面墙已移出 Demo；背景账号不开放登录，启动输出不列账号清单。成员体验账号在黑客松墙的初始页面仍为空白，方便完整创作。

快捷登录只接受同源 POST 中的固定 `identity=member|organizer`，不能提交任意邮箱、用户 ID、权限或跳转地址。由服务端创建正常会话，只在数据库存会话令牌哈希。登录后统一进入首页，首页不展示身份切换卡片。顶部“切换身份”回到双入口页，选择后销毁当前会话并创建新会话；“退出登录”沿用会话、来源和 CSRF 校验。演示模式的邮箱发码、验证码验证与会话加载也限制为上述两账号；开发发件箱不开放。普通开发的邮箱登录保持原行为。

评委无需访问 AI 设置：工作区与采访页提示“演示模型已配置，无需填写 API Key”，模型费用由演示提供者承担。演示模式不提供模型设置页面或菜单入口，相关页面与保存、删除接口均返回 404；维护者预置模型照常供创作使用，不影响普通账号的自带 API 管理。调用失败显示固定中文原因与重试指引，不展示服务商原始响应或 Key。

## 验收方法

1. 配好维护者模型，运行 `pnpm demo`。默认主站 `http://localhost:3000`，页面源 `http://127.0.0.1:4000`。端口被占用时先处理已有服务，或显式使用 `NOWME_WEB_ORIGIN=http://localhost:3400 NOWME_PAGES_ORIGIN=http://127.0.0.1:4400 pnpm demo`。
2. 从成员入口先进入首页，再选择黑客松墙的创作工作区，浏览墙和人物卡片，再开始采访、确认资料、生成、预览、修改，最后本人确认发布。iframe 继续为 `sandbox="allow-scripts"`，页面来自独立源。
3. 切换为组织者，检查成员发布状态与邀请；他人的 brief / 草稿不可访问。退出后会话失效。
4. 类型检查 `pnpm typecheck`；自动化 `pnpm test`；安全回归 `pnpm test:security`。新增测试见 `apps/web/test/security/demo-*.security.test.ts`。
5. 普通 `pnpm test:e2e` 保留现有确定性测试；真实演示验收脚本为 `tests/e2e/demo.e2e.ts`，只有显式提供 `NOWME_DEMO_E2E_ORIGIN` 才运行，且需另行启动已配置的演示服务。执行：`NOWME_DEMO_E2E_ORIGIN=http://localhost:3400 pnpm exec playwright test --config playwright.demo.config.ts`（先以对应端口启动演示）。真实调用会产生服务商费用，测试结果不能用假模型替代。
