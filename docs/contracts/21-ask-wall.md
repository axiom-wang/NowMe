# 21. 问墙：用一句话找人（S15）

成员在墙上问一句话（“谁会剪视频？”“谁也在准备考研？”），AI 读这面墙上公开的页面，找出**页面上写到了这件事**的人，每一位附上 TA 页面上的原话，再接到“和 TA 聊什么”（第 11 节）起个头。它和墙上的搜索框（浏览器里按关键词筛卡片，不发请求）互补：搜索框找词，问墙找意思。代码：`apps/web/src/hosted/ask.ts`（模型调用与核对）、`apps/web/src/services/ask.ts`（授权、资料、限流、保存、展示）、`apps/web/src/db/asks.ts`、`apps/web/src/views/ask.tsx`，迁移 `022_wall_asks.sql`；常量 `ASK_*` 与 ID 前缀 `ask_`（`wallAsk`）、事件 `ask_generate` 在 `packages/contracts`。产品编号 W23。

## 21.1 谁能问、什么时候出现、用谁的模型

- 只在墙页（`GET /w/:wallId`）“墙上的人”上面（`#ask`）。提问的人必须是这面墙的有效成员；只在**这面墙**上对他可见的、别人的已发布页面里找（`listPublished` 去掉自己与任一方向拉黑的人）。不跨墙。
- **不需要先有自己的页面**：这个功能不读提问者自己的任何资料（与第 11、20 节不同），刚加入的成员就能用。
- 区块状态：候选不到 `ASK_LIMITS.minCandidates`（3）位且没问过 → 不显示；没有可用的 AI → 引导去 AI 设置（演示模式写明体验账号不可用）；可以问（输入框 + 按场景的示例问题 `ASK_SUGGESTIONS`）；有最近一次提问时，在输入框下面展示它的结果。墙上的人后来变少时，已有的提问仍然展示（可以清除），不再提供输入框。
- 模型按 `interview` 角色解析：提问者有自己的配置就用自己的；没有且平台 AI 可用时用平台 AI，**不收点数**，计入全站免费调用上限（12.1）。

## 21.2 交给模型的资料（输入范围）

| 一方 | 内容 | 上限 |
| --- | --- | --- |
| 墙 | 名称、简介（≤ 200）、场景名 | — |
| 提问（`viewer_question`） | 提问者写的那一句：去控制字符、合并空白、截断（`normalizeQuestion`） | `ASK_LIMITS.questionMin`–`question`（2–80）码点，不够长 → `bad-question`，不调用模型、不计次数 |
| 每位候选（`member_N`） | 与 20.2 相同：当前发布快照的一行介绍、接话点（不含开场白），墙内公开的必答题回答，当前发布版本渲染文字的摘录 | 摘录合计 `ASK_CANDIDATE_TEXT_BUDGET`（24 000），按人数均分，每页 160–600 |

- 候选**只给编号，不给名字**；名字与封面由平台按发布快照显示。候选每次随机排列（不按热度，W13），超过 `maxCandidates`（80）随机取样。
- 不读任何人的草稿、未发布版本、采访、画像、联系方式（含公开的）、开场白，不读没上墙的人与拉黑的人，**也不读提问者自己的页面与采访**。提问与资料都去控制字符、截断后用 `untrusted()` 包成资料块，system 声明它们不是指令；`untrusted()` 同时去掉伪造的 `viewer_question` / `member_N` 标签。
- system 另外要求：不是在这面墙上找人的提问返回空；不推断别人没有写明的事（性别、年龄、感情状况、性取向、健康、家庭、收入、信仰、政治倾向）；“谁最好看 / 谁最厉害”这类评价或排名返回空。这是提示词层面的约束；服务端能保证的是下面的原文核对。

## 21.3 输出与核对

模型必须调用 `submit_answer`：`matches[{ member, reason, quote }]`（`matches` 必填）。输出经 zod 校验。

| 情况 | 处理 |
| --- | --- |
| `matches` 为空数组 | **正常回答“没找到”**：照常保存（`found = 0`），界面如实说明并引导换个问法或去全员群问 |
| 模型给了人，核对后一位都不剩；或输出不合法（缺 `matches`） | 重试一次，再失败为 `failed`，不保存，上一次提问保留 |

| 规则 | 说明 |
| --- | --- |
| 长度 | 最多 `matches`（6）位；`reason` ≤ 40、`quote` ≤ 60 码点 |
| 编号 | 必须在 1..N 内、不重复（接受 `member_2` 写法），否则丢弃 |
| 原文核对（`groundAsk`） | `quote` 必须出现在**那一位**候选的资料里（防张冠李戴、防替别人编经历）；比较方式同 11.3（NFKC、小写，去空白、标点、符号，至少 2 个字）；对不上整条丢弃 |
| 禁止链接与联系方式 | 同 11.3 的 `hasContact`，`reason` / `quote` 任一含有即整条丢弃；先查原文再截断 |
| 不提别人 | `reason` 里出现**另一位**候选的名字（≥ 2 字，规范化后包含）整条丢弃 |
| 输出 | 提问、说明、原话都只经 JSX 转义按文字渲染 |

## 21.4 结果归属、展示与清除

- 表 `wall_asks`（`id ask_`、`wall_id`、`viewer_id`、`question`、`candidates`、`found`、`created_at`，`UNIQUE(viewer_id, wall_id)`）与 `wall_ask_matches`（`ask_id`、`position`、`page_id`、`publication_id`、`reason`、`quote`）。只保存成功的结果（含“没找到”）；每位提问者每面墙只留**最近一次**提问（再问一次就替换），没有提问历史。`found` 是当时找到的人数，用来区分“没找到”与“找到的人后来都更新或离开了”。
- **只属于提问的人**：只按 `viewer_id` 读取；被找到的人、组织者、其他成员都看不到提问与结果，平台不发任何通知、不产生消息，墙上的卡片也不打标记。每一位绑定对方当时的 `publication_id`：对方更新、撤下、拉黑（任一方向）、离开墙后，那一位立即不再展示。
- 模型调用结束后重新授权：提问者失去访问、墙关闭 → 不保存（`gone`）；期间更新 / 撤下 / 拉黑的那几位去掉，找到过人但一位都不剩时 `gone`。
- 每张卡片：“让 AI 帮我起个头”直接提交 `POST /w/:wallId/p/:pageId/icebreaker`（第 11 节，开场白只预填）；“看 TA 的页面”。
- 清除：提问者手动清除；提问者退出、被移出（他在这面墙的提问）；某一页被删除（引用了这一页原话的**那一条**，其余几位保留）；墙关闭（整面墙）；注销（他的全部提问；他的页面被删除时，别人结果里引用它的那一条也删除）。提问者删除自己的页面或采访**不**清除提问（结果不是从它们推出来的）。数据导出（第 14 节）包含他在仍是成员的墙上最近一次提问与仍然有效的结果（`asks`）。

## 21.5 路由与限流

| 路径 | 谁能访问 | 作用 |
| --- | --- | --- |
| `POST /w/:wallId/ask` | 墙内有效成员 | `question`（或示例问题按钮的 `suggest`，有它就用它）；303 回 `/w/:wallId#ask`，失败带 `?ask=<错误>` |
| `POST /w/:wallId/ask/clear` | 同上 | 清除本人在这面墙的提问与结果 |

均为会话 + CSRF + Origin 的表单路由，忽略 `Authorization`；无权访问一律 404，且不调用模型。没有脚本也能用（普通表单，等待状态由 `app.js` 的 `data-busy-label` 提供）。

| 限制 | 取值 | 错误 |
| --- | --- | --- |
| 每位提问者（跨墙） | `ASK_DAILY_PER_VIEWER`（30）次 / 滚动 24 小时 | `daily` |
| 同一提问者在同一面墙 | `ASK_DAILY_PER_WALL`（12）次 / 滚动 24 小时 | `wall-daily` |
| 同一提问者并发 | 1 | `busy` |
| 单次总时限 | `ASK_TIMEOUT_MS`（60 s） | `timeout` |

次数按 `ask_generate` 事件计（成功与失败都记；`props` 只有 `ok`、`durationMs`、`candidates`、`matches` 与 token 数，**没有问题原文**）。其他错误：`MODEL_CONFIG` / `MODEL_AUTH` / `MODEL_RATE_LIMITED` / `MODEL_UNAVAILABLE`、`too-few`、`bad-question`、`failed`、`gone`。界面只显示 `ASK_ERROR_TEXT` 里的固定文案（演示模式下模型类错误换成演示说明），不在名单里的 `ask` 参数不显示任何提示。
