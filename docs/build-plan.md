## 工作方式

- 总规划师不写业务代码；实现由子 Agent 完成，总规划师写规划与文档、读代码、亲自运行测试做验收。
- 每个任务说明写清：读 contracts 的哪几节（文件名）、只改哪些目录、验收标准、必须附带的测试。不要让子 Agent 通读 `docs/`。
- 并行任务各用独立 git worktree，按目录划分归属，合并回 `main` 后统一验收。
- 子 Agent 汇报完成不等于完成：总规划师亲自运行测试与命令，通过后才标 ✅。
- 安全不变量（contracts 05 及各节的 S7–S15）必须有自动化测试，并由独立子 Agent 审查。
- 子 Agent 模型分配：机械性任务用 Sonnet；规划、安全审查、Skill / 示例页等需要判断的任务用 Opus。
